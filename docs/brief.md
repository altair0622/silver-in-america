# 실버 프로젝트 — 시작 브리프

> 이 문서는 claude.ai 대화에서 정리한 내용을 Claude Code로 넘기기 위한 인수인계 글입니다.
> 공통 가이드라인은 컨트롤 타워 폴더의 CLAUDE.md를 우선 따릅니다. 이 문서는 프로젝트 고유 내용만 담습니다.

## 1. 배경

부모님(미국 거주 한인 시니어)과 이야기하면서 나온, 미국에 사는 한인 실버들의 고충 세 가지에서 출발한 프로젝트입니다.
세 가지의 공통점은 **"자녀에게 매번 묻기 미안한 일"** 이라는 점입니다. 그래서 모든 기능에서 **가족(자녀)이 함께 보고 도울 수 있는 구조**를 핵심 장치로 둡니다.
첫 사용자는 부모님입니다. 실제 사용 피드백을 받으며 키웁니다.

## 2. 세 가지 아이디어와 우선순위

| 순위 | 아이디어 | 방향 | 상태 |
|---|---|---|---|
| 1 | 공과금 확인 | 예정일 vs 실제 출금일 비교, 안 나갔으면 이유 후보 안내 | **지금 시작 (MVP)** |
| 2 | 언어 도움 | 번역 앱이 아니라 "가기 전 준비 / 대신 전화 / 다녀온 후 요약" | 다음 단계. 집 견적 AI의 음성 에이전트 기술 재사용 검토 |
| 3 | 신뢰 (AI 시대에 누구를 믿을까) | 앱보다 글·콘텐츠. AI 엔지니어링 사이트의 시리즈 후보 | 코드 작업 대상 아님 |

## 3. MVP: 공과금 확인 앱

### 해결하려는 문제
- 계좌가 여러 개(예: 3개)이고, 각 계좌에서 여러 유틸리티 요금이 나간다.
- "이번 달 진짜 나갔나? 안 나갔으면 왜?"를 한 화면에서 확인하고 싶다.
- 부수 효과: "전기 끊긴다, 지금 기프트카드로 내라" 같은 시니어 대상 사기 전화에 대해 "정상 출금됨"을 바로 확인할 수 있으면 방어가 된다.

### 데이터 모델 (초안)
- **계좌(Account)**: 이름(별칭), 은행명, 끝 4자리 정도만. 전체 계좌번호는 저장하지 않는다.
- **청구 항목(Bill)**: 업체명(예: Georgia Power, Gwinnett County Water), 종류(전기/수도/가스/인터넷/폰/보험 등), 연결 계좌, 예정일(매월 n일), 예상 금액(범위 허용), 납부 방식(자동이체/카드/수동).
- **월별 기록(Payment)**: 해당 월, 실제 출금일, 실제 금액, 상태, 메모.

### 상태는 세 가지만
- ✓ **나감** — 실제 출금 확인됨
- ⏳ **아직** — 예정일 전
- ⚠ **안 나감** — 예정일(+유예 n일)이 지났는데 확인 안 됨
  - 이유 후보를 한국어로 표시: 카드 만료, 자동이체 해제, 금액 변동, 잔액 부족, 청구서 미발행 등

### 화면
1. **이번 달 한눈에**: 계좌별로 묶은 청구 목록 + 상태 아이콘. 큰 글씨, 한국어 우선.
2. **확인 체크**: 항목을 눌러 "나감" 처리 (날짜·금액 입력). 1단계는 수동 확인.
3. **항목 등록/수정**: 업체, 계좌, 예정일, 금액.
4. **지난 달 기록**: 월별 히스토리.

### 1단계 범위 (일부러 작게)
- 수동 등록 + 수동 체크로 시작. **은행 연동(Plaid 등)은 1단계에서 하지 않는다.** 보안·비용·심사 부담이 크다.
- 2단계 후보: 은행 알림 이메일 / 명세서 사진을 읽어서 "나감" 자동 체크 (AI 사용).
- 3단계 후보: 가족 공유 — 경고가 뜨면 자녀에게도 알림. 이때 백엔드 필요.

### 시니어 UX 원칙
- 기본 글자 크기 크게, 버튼 크게, 한 화면에 한 가지 일.
- 영어 업체명은 그대로 두되 설명·상태·안내는 한국어.
- 아이콘만으로 의미를 전달하지 말고 항상 글자를 함께.

## 4. 기술 메모 (Claude Code와 같이 결정할 것)
- 기존 방식처럼 **PWA + GitHub Pages**(altair0622)로 시작하면 빠르다. 1단계는 데이터를 기기 안(localStorage/IndexedDB)에만 두면 서버 없이 가능.
- 단점: 기기를 바꾸거나 데이터를 지우면 사라짐 → 내보내기/가져오기(JSON) 기능을 1단계에 포함.
- 가족 공유(3단계)부터는 백엔드와 로그인이 필요. 그때 다시 결정.
- 금융 정보는 최소한만: 계좌번호·카드번호 전체는 절대 저장하지 않는다.

## 5. Altair Research Lab 공통 원칙 적용
- **AI 의존도 표시**: 1단계는 AI 사용 없음(0). 2단계 이메일/사진 판독부터 AI 사용 — 리스팅에 명시.
- **AI는 실수를 인정한다**: 자동 판독 결과에는 확신 정도를 보여주고, 사용자가 쉽게 고칠 수 있게.
- **사람의 한 스푼**: 예) 가족(자녀)이 확인해 주는 체크, 또는 손글씨 같은 따뜻한 안내 문구.
